Repair SILVAH 8, prove every fix against known-good runs

The Forest Service's 4 November answers narrow this work to repairing SILVAH 8, a Windows desktop application of about 81 C++ files built in Visual Studio 2019, with no version control and no automated test suite. This workbench shows how Agentic Rx would handle each of the three defects the Government named, and how every change is checked against the reference stand files before it reaches the scientists.

Defect 1

Middle plot not in the stand table

The 16 ft radius middle plot feeds stump-sprout prediction but its sapling-layer trees are never merged into the overall stand table.

Defect 2

Thinning prescriptions unreachable

A wrong branch in the prescription flow chart means the program cannot reach a thinning recommendation.

Defect 3

FSVEG interface broken

The link to FSVEG stopped working when the Government restricted command-line SQL calls.

How we work on the code (from the Government's answers)

  • Put the delivered source under Git on day one, so every change is reviewed, reversible and documented, alongside the existing in-code comments.
  • Rebuild in Visual Studio with the 2019 (v142) toolset first, then confirm it runs on the Windows versions in use before changing any logic.
  • Turn the known-good SILVAH files into an automated regression suite, so each fix is compared with the reference outputs.
  • Any AI coding assistant runs on our own machines only, with no cloud upload of SILVAH code. That matches the Forest Service's condition.
  • Scientists confirm the silvicultural rules. We never change an equation or a threshold without their written agreement.
  • Deliverables: full source, build scripts, tests and an installer, with Government rights to all of them.

Defect 1: merge the 16 ft middle plot into the stand table

Sapling-layer trees (1.0 to 5.9 in. dbh) are tallied on a fixed-area 16 ft radius plot at each sample point. One tree on one plot represents 43,560 ÷ (π × 16²) = 54.16 trees per acre. Once that tally is averaged over the sample points, it should become the sapling rows of the stand table, so that density, stocking and the prescription all see it.

Defect 3: replace the command-line SQL link to FSVEG

SILVAH 8 reached FSVEG by shelling out to a command-line SQL client, which Forest Service policy now blocks. The fix is to move the query inside the application through an approved, authenticated connection, and to keep a file-import fallback so users are never stranded.

Today: blocked

// illustrative
std::string cmd = "sqlplus " + user + "/" + pwd + "@FSVEG @stand.sql "
                + standId + " > out.csv";
system(cmd.c_str());          // blocked: command-line SQL restricted
importCsv("out.csv");         // credentials on the command line, temp file

After repair

// illustrative: in-process, parameterised, no shell
FsvegSession s = FsvegSession::open(authToken);   // FS-approved sign-in
auto q = s.prepare(
  "SELECT plot, species, dbh, tpa FROM tree_view WHERE setting_id = ?");
q.bind(1, settingId);                              // no string-built SQL
for (auto& row : q.execute()) stand.addTree(row);

Regression harness: every build compared with known-good runs

The Forest Service validates new versions by comparing them with known-good runs and hand calculations. We automate exactly that: each reference stand file runs through the build, and its outputs are compared with the accepted values within a tolerance agreed with the scientists. A change only merges when every row is green, or when a difference is the intended result of a fix and the scientists have signed it off.
